# THE OTHER SIDE — TESTS

Testing begins with implementation and continues through production validation.

## Mandatory Validation Areas

1. Coordinate integrity
2. Room connectivity
3. Portal validity
4. Vertical clearance
5. Collision/visual agreement
6. Circuit dependency integrity
7. Save-terminal accessibility
8. Act III blind-spot escape continuity
9. Mirror observation causality
10. Save/load state restoration
11. Technician vulnerability causality
12. Final escape causality

## Coordinate Test

Source coordinates, exported coordinates, imported coordinates and collision coordinates must preserve the same spatial relationships.

## Topology Test

No canonical room may become disconnected.

No portal may connect spaces that do not physically meet.

## Mirror Test

Every significant Mirror intervention must be traceable to:

**Observed data → learned pattern → contextual prediction → intervention**

The Mirror may not use player intent, hidden engine state, unobserved information or failed-timeline memory.

## Technician Test

The implemented legacy vulnerability must remain consistent with the locked design principle:

**pre-existing physical infrastructure + information asymmetry + technician knowledge**

The exact hardware may vary, but the implementation must not turn the vulnerability into a new unrelated puzzle or supernatural mechanic.

## Escape Test

The canonical route must remain:

**VC-01 → R-401 → C-403 → R-402 → R-403 → C-499 → Exterior**

C-499 must provide the intended genuinely unmonitored final transition.

The escape must be caused by the locked combination of technician knowledge, Mirror understanding, information asymmetry and deliberate pattern violation.

## Regression Rule

A later implementation change must not silently alter frozen architectural truth or core gameplay causality.
